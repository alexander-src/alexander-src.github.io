Selected work

Flagship build: x86-64 binary ISA auditing

isa-audit

Shipped v0.1.0 / MIT License / Zero external crates

A single stray FMA3, AVX2, or AVX-512 instruction in a cold branch crashes older CPUs with SIGILL. isa-audit parses x86-64 ELF64 executables and object files directly in safe Rust (#![forbid(unsafe_code)]), decodes legacy, REX, VEX2, VEX3, and EVEX encodings, and fails CI with the exact section, virtual address, symbol offset, and raw bytes.

Built to verify portable release binaries and instruction-lowering passes such as targeting non-FMA AVX hosts (--target avx-no-fma).

  • Decode throughput 281.6 MiB/s (70.1M insns/s)
  • Binary footprint 427 KB stripped release
  • Dependencies / unsafe 0 crates / forbidden
  • Verification oracle 6 live g++ -O2 kernels + objdump
  • CI report formats Text, JSON, SARIF 2.1.0

How I work with AI

Fast generation only counts when verification catches real bugs.

Writing boilerplate by hand is slow, so I use coding agents to draft modules and test harnesses quickly. Before an agent writes implementation code, I write a short SPEC.md and ARCHITECTURE.md that fix the data structures, safety boundaries, and exit codes. That keeps architecture decisions in my hands instead of letting a model invent abstractions on the fly.

The real test is what happens when generated code meets real tools. During isa-audit development, synthetic unit tests passed on the first run, yet compiling real object files with g++ -c -mfma exposed a missing symbol bug on ET_REL sections at offset 0x0, and auditing our own Rust binary with objdump caught 26 false positives caused by baseline tzcnt (rep bsf). Both bugs, their disassembly traces, and their fixes are documented in the isa-audit case study.
