Engineering Case Study 01

Building isa-audit: Zero-Dependency x86-64 ELF Verification at 281 MiB/s

How upfront constraints and live g++ and objdump checks produced a 427 KB safe-Rust binary auditor and uncovered two real x86-64 and ELF defects that synthetic unit tests missed.

View source on GitHub Back to portfolio

1. Problem and Constraints

When compiling portable Linux releases or writing binary relinkers and instruction-lowering passes (such as lowering FMA3 or AVX2 down to baseline AVX), a single unlowered instruction in a rarely reached branch raises SIGILL on older CPUs. Standard unit tests only exercise executed paths.

Before implementation began, docs/SPEC.md locked down four non-negotiable rules:

  • Zero external crates ([dependencies] stays empty) for instant offline builds and minimal binary size.
  • Memory safety enforced at compile time via #![forbid(unsafe_code)] with bounds-checked slice reads and checked arithmetic on every ELF offset.
  • Clean CI exit codes (0 pass, 1 policy violation, 2 I/O or malformed ELF error) with Text, RFC 8259 JSON, and SARIF 2.1.0 outputs.
  • Ground-truth verification against live C++ kernels compiled with g++ -O2 across six distinct -m* flag sets.

2. Architecture

  • Function-boundary resynchronization: When .symtab or .dynsym provides STT_FUNC spans, analyzer.rs restarts decoding at every function boundary so inline jump tables or inter-function padding cannot desynchronize subsequent functions.
  • Stack-only hot loop: decode_one(&[u8]) -> DecodedInsn performs zero heap allocations per instruction and only materializes Finding records on forbidden instructions.
  • Strict 64-bit encoding validation: Rejects illegal combinations (such as legacy 0x66 before VEX 0xC4, VEX map values outside 1..=3, or EVEX prefixes missing P1.bit2 == 1) and handles no-ModRM VEX exceptions like vzeroupper (C5 F8 77).

3. Two Real Bugs Caught by Verification

AI coding assistance accelerated opcode dispatch tables, header parsing, and CLI scaffolding. However, two subtle defects passed every initial unit test and only surfaced when testing against real GCC output and real Linux binaries.

Bug 1: Symbol attribution dropped on ET_REL object files

The initial symbol loader skipped entries with st_value == 0 to filter undefined external imports. That passed synthetic linked ET_EXEC binaries (where .text sits at 0x401000), but failed when tests/gcc_ground_truth.rs compiled a real g++ -c -mfma object file (.o). In relocatable object files, the first function in .text legitimately starts at offset 0x0, so attribution silently returned None.

Fix: Filtered undefined imports using proper ELF rules (st_shndx != SHN_UNDEF) and scoped symbol lookups by (section_index, vaddr) so multiple executable sections starting at offset 0x0 inside an ET_REL file never collide.

Bug 2: 26 false positives from baseline tzcnt (F3 0F BC)

Following standard opcode tables, the decoder initially mapped F3 0F BC (tzcnt) to BMI1. Scanning isa-audit's own release binary immediately caught the problem: it claimed a baseline x86-64-v1 Rust binary required x86-64-v3 with 26 BMI1 violations. Inspecting address 0x36574 with objdump -d showed why: 

36570: 85 c0          test   %eax,%eax
36572: 74 0e          je     36582
36574: f3 0f bc c0    tzcnt  %eax,%eax   ; executes as rep bsf on pre-BMI1 CPUs

On pre-BMI1 x86-64 CPUs, F3 0F BC executes as REP BSF without raising #UD or SIGILL, and yields identical results for non-zero inputs. Reclassifying F3 0F BC as Baseline (tzcnt/rep-bsf) removed all 26 false positives while keeping strict detection for faulting VEX-encoded BMI1 instructions (andn, blsr, blsmsk, blsi, bextr).

Lesson: Hand-written unit tests check what you assumed. Real compiler output (g++) and real disassembly (objdump) check what actually runs on x86-64 silicon.
